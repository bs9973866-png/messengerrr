# Мессенджер

Свой веб-мессенджер: работает в браузере на компьютере и телефоне, данные хранятся на вашем сервере.

## Возможности

- Регистрация и вход (логин + пароль), поиск людей по имени или логину
- Личные чаты и группы (до 200 участников), добавление участников, выход из группы
- Текстовые сообщения: ответы, редактирование, удаление у всех, ссылки кликабельны
- Голосовые сообщения с волной, перемоткой и скоростью 1× / 1,5× / 2×
- Видеосообщения-«кружки» (до 60 секунд)
- Файлы до 100 МБ (кнопка 📎, перетаскивание, вставка из буфера), фото и видео показываются в чате
- Аудио- и видеозвонки 1 на 1 (WebRTC): выключение микрофона и камеры, показ экрана, история звонков в чате
- «Печатает…», статус «в сети», галочки доставки/прочтения, счётчик непрочитанных
- Уведомления браузера, тёмная тема, адаптивная вёрстка под телефон

## Запуск

```bash
npm install
npm start
```

Откройте http://localhost:3000.

## Важно для звонков, микрофона и камеры

Браузеры разрешают микрофон и камеру **только на HTTPS или на localhost**. Чтобы пользоваться
мессенджером с других устройств, нужен домен с HTTPS. Самый простой путь — обратный прокси
(Caddy или nginx) с сертификатом Let's Encrypt; в таком случае запускайте с `TRUST_PROXY=1`.
Либо передайте свой сертификат: `HTTPS_KEY=key.pem HTTPS_CERT=cert.pem npm start`.

Если звонок не соединяется (строгий NAT, мобильные сети), нужен TURN-сервер (например, coturn):

```bash
TURN_URL=turn:turn.example.com:3478 TURN_USER=user TURN_PASS=pass npm start
```

## Настройки (переменные окружения)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | 3000 | порт |
| `DATA_DIR` | `./data` | база (`db.json`) и загруженные файлы |
| `MAX_UPLOAD_MB` | 100 | максимальный размер файла |
| `STUN_URLS` | публичные STUN Google | список через запятую |
| `TURN_URL`, `TURN_USER`, `TURN_PASS` | — | TURN для звонков |
| `TRUST_PROXY` | — | `1`, если сервер за прокси |
| `HTTPS_KEY`, `HTTPS_CERT` | — | запуск сразу по HTTPS |

## Безопасность

Пароли хранятся в виде scrypt-хэшей, сессии — в виде хэшей токенов (cookie `HttpOnly`). Файлы доступны только участникам
чата, «опасные» типы (HTML и т. п.) всегда отдаются как скачивание. Есть защита от чужих origin, ограничение попыток входа
и частоты сообщений. Сообщения хранятся на сервере в открытом виде (сквозного шифрования нет), звонки идут напрямую
между участниками (шифруются средствами WebRTC).

## Ограничения и что можно добавить дальше

Хранилище — один JSON-файл: этого хватает для сотен пользователей и небольших команд; для больших нагрузок стоит
заменить его на SQLite/PostgreSQL. Групповых звонков пока нет (только 1 на 1). Нет push-уведомлений при закрытой вкладке.

## Проверка

`npm test` запускает сквозной тест сервера (21 проверка: чаты, файлы, звонки, права доступа).

## Размещение на бесплатном хостинге (Render)

GitHub Pages для этого не подходит: он отдаёт только статические файлы, а мессенджеру нужен работающий сервер.

1. Загрузите папку проекта в репозиторий GitHub (без `node_modules` и `data`, они в `.gitignore`).
2. На render.com: **New → Blueprint** (или **Web Service**), выберите репозиторий. Настройки подхватятся из `render.yaml`.
   Если создаёте вручную: Build `npm install --omit=dev`, Start `npm start`, переменная `TRUST_PROXY=1`.
3. Через минуту-две появится адрес `https://имя.onrender.com`. Отправьте его собеседнику: HTTPS уже есть, звонки и микрофон работают.

Ограничения бесплатного тарифа: сервис засыпает после ~15 минут без активности (первый заход потом грузится около минуты),
а диск временный: при перезапуске и обновлении аккаунты, сообщения и файлы стираются. Для постоянного хранения нужен
платный диск (в `render.yaml` добавляют `disk` и `DATA_DIR` на него) или другой хостинг с томом.
